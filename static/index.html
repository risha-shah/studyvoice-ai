WHAT I WANTED TO LEARN

More than a chatbot.

I built StudyVoice to understand the full loop behind a real-time voice product: capture intent, call backend services, handle failures, return a useful answer, and make the interaction feel natural.

01

Voice interface

Browser speech recognition captures natural questions without requiring typed input.

02

API orchestration

A Flask REST endpoint validates requests, calls the model layer, and returns structured responses.

03

Conversational output

Responses are optimized for listening and spoken back using browser text-to-speech.

04

Failure-aware design

Mock mode, API error states, health checks, and graceful voice fallbacks keep the demo usable.
